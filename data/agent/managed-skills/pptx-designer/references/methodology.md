# PPT 制作方法论（methodology.md）

> 制作专业汇报 PPT 的完整决策框架。核心：**内容决定版式，风格统一色调，每页一个明确设计依据**。
> **第一铁律：内容是汇报材料，绝不妥协。模板只是视觉增强，没有合适模板就手搓，禁止为套模板改内容。**

## 一、六步流程（内容优先，用户确认制）

| 步骤 | 产物 | 决策 | 确认点 |
| --- | --- | --- | --- |
| 0 文字稿 | 文字稿（外部技能/用户提供/材料提取） | 只有主题时先出文字稿，不允许无稿进大纲 | — |
| 1 大纲 | OUTLINE.md（**每页含布局类型**） | 叙事 → 页骨架 → 每页内容类型+布局类型+结论；装不下标拆页 | **用户确认（页数可增删）** |
| 2 主题 | design.json（色板/字体/主题 ID） | 用户指定 / 上传模板逆向 / 场景推荐 | **用户确认** |
| 3 细化设计稿 | DESIGN.md（每页文字/分布/卡片/图片/强调） | 内容类型 → 布局 → 文字 → 卡片 → 图位 → 强调用法 | — |
| 4 模板匹配 | 每页 layout key 或「手搓」 | 按内容查 layout-catalog.md；无合适就手搓 | — |
| 5 逐页生成 | pages/slide_XX.js | layout 引用 或 DSL 手搓，对照 DESIGN.md | — |
| 6 编辑器/导出/交付 | editor.html + deck.pptx/pdf + 最终.pptx | 用户编辑器调整 → 确认后编译 | **导出确认** |

**决策顺序（不可倒置）**：文字稿 → 内容 → 布局 → 主题 → 设计稿 → 模板。
禁止"先挑好看版式再硬塞内容"，也禁止"为了用某模板删改内容"。

## 二、大纲每页必填（OUTLINE.md 契约）

| 字段 | 说明 |
| --- | --- |
| 页面定位 | 封面/目录/章节/内容/结束 |
| 内容类型 | 数据/KPI、对比、流程、图片、观点、列表… |
| 布局类型 | L-* 模式（layout-library.md 选） |
| 本页结论 | 一句话——这页要传达什么 |
| 拆页标记 | 装不下标 5a/5b，设计稿阶段展开 |

大纲由用户确认（页数可增删）后才进入主题与设计。

## 三、设计稿每页必填（DESIGN.md 契约）

| # | 字段 | 说明 |
| --- | --- | --- |
| 1 | **本页结论** | 一句话，说不清这页不过 |
| 2 | **文字内容与分布** | 标题/正文/数字，哪些字放哪块区域 |
| 3 | **卡片格式** | 几块卡片/色块/列表/表格，内容怎么装 |
| 4 | **图片张数与图位** | 0-4 张，先定图位再组织文字 |
| 5 | **强调用法** | 全局色调下强调色用在哪（某数字/系列/色块，≤10% 面积） |
| 6 | **拆页落实** | 拆页页展开为两页，各写清内容 |

> **色调是全局的**——主题选择（Step 2）时确定，设计稿每页不重复选色调，只标强调用法。

## 四、内容类型 → 布局类型 决策矩阵

| 内容类型 | 布局类型 | 强调用法建议 |
| --- | --- | --- |
| 开场/封面 | L-cover | 主色大面积 + 强调色点缀 |
| 导航/目录 | L-toc | 主色 40% + 强调色编号 |
| 章节切换 | L-section | 主色 60% + 强调 15% |
| 核心数据/KPI | L-metrics / L-duel | 强调色 15-20%（荧光/高饱和） |
| 趋势/时间序列 | L-trend | 图表双色（主 + 对比） |
| 排行/分布 | L-ranking | 表头主色 + 高亮强调 |
| 对比/问题对策 | L-compare | 双栏各一强调色 |
| 流程/步骤 | L-process | 编号强调色循环 |
| 架构/关系 | L-network | 主色阶 + 少量强调 |
| 观点/结论 | L-conclusion / L-quote / L-statement | 主色 + 金句强调 |
| 图片/场景 | L-photo-left/right/top | 图承载色调，文字用中性 |
| 团队/案例集 | L-grid | 统一图框 + 主色标签 |
| 人物反馈 | L-portrait | 主色边框 + 中性底 |
| 项目拆解 | L-case | 图 + 编号强调 |

## 五、页级模板匹配（Step 4：目录查模板，无合适就手搓）

**流程**：每页按「内容类型 + 布局类型 + 文字量 + 图量」查 `layout-catalog.md`：

1. **查类别**：先在快速对照表定位类别（封面/大数字/KPI/图表·趋势/对比/排行…）
2. **看候选**：读该类别的布局表（key | label | slot），按 label 语义匹配本页内容
3. **选定**：优先所选主题内的布局（themeXX_pageNNN），同 slot 多主题成套
4. **无合适 → 手搓**：手搓 DSL 是正常路径，不是降级

**红线（不可违背）**：
- 模板与内容冲突 → 换模板或手搓，**绝不改内容**
- 模板装不下内容 → 拆两页，不压缩内容
- 模板字段与内容类型不匹配 → 手搓，不硬套

**文字量 × 图量 自检**：少文字页禁堆正文；多文字页禁大图撑版面；图表页必须有洞察；图片页必须有图说。

## 六、色调选型（全局，Step 2 主题选择时定）

1. **用户指定** → 直接用（"用 theme02 炫光紫绿风"）
2. **模板模仿** → profile_template.js 分析上传模板色板/字体
3. **场景推荐** → 从 dashiai-styles.md 12 套按场景选（金融→theme10、科技→theme02、数据报告→theme05/06、政务→redgold、学术→academic），ask 用户确认
4. **默认** → 商务浅色（academic 蓝白）

**风格统一纪律**：全篇一套色板（≤4 hex）+ ≤2 字体；风格只约束色板/字体/视觉语言，**不约束布局**（布局永远由内容决定）。

## 七、硬约束（每页自检）

1. 大纲字段齐全、设计稿六要素齐全，决策顺序正确（内容→布局→主题→设计稿→模板）
2. 每页 ≥1 视觉锚点（巨型数字 ≥48px / 图 ≥40% B 区 / 大色块）
3. 相邻页布局模式不重复；对称版式全篇 ≤2 页
4. 图片位先定（L-photo*/L-grid），文字围绕图组织
5. 配色 ∈ design.json palette；字号符合阶梯；文本不溢出
6. 内容页必有母版（标题块 + 页码）；hero 页有冲击力版式
7. **内容完整性**：模板/布局不得导致内容删减或扭曲——违反即返工

## 八、OUTLINE.md 每页样例

```markdown
| # | 定位 | 内容类型 | 布局类型 | 本页结论 | 拆页 |
| 01 | 封面 | 开场 | L-cover | 主题+汇报人 | — |
| 02 | 目录 | 导航 | L-toc | 五部分导航 | — |
| 03 | 章节 | 章节 | L-section | 进入市场规模 | — |
| 04 | 内容 | 核心数据 | L-metrics | 市场规模 3200 亿 | — |
| 05a | 内容 | 趋势 | L-trend | 五年增速翻倍 | 拆页 |
| 05b | 内容 | 对比 | L-duel | 新旧两代对比 | 拆页 |
```

## 九、DESIGN.md 每页样例

```markdown
## 页 04 · 市场规模（L-metrics → layout-catalog「大数字/KPI」查模板）
- 本页结论：市场规模 3200 亿元，CAGR 23%
- 文字分布：左标题 40 号；中间 3 个巨数字（72px）；底部洞察条 16 号
- 卡片格式：3 块数字卡（值+标签+同比箭头）
- 图片张数：0（纯数字）
- 强调用法：第 2 个数字荧光绿强调
- 模板匹配：theme01_page006 大数字·资本体量 合适 → layout: 'theme01_page006'
```

设计稿完成后，逐页生成时**严格对照六要素实现**，完成即验收。
