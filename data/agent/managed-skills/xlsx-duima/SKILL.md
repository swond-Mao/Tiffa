# 表格对码管线（xlsx-duima）

把「业务总表」（每行一个在用的耗材/药品，字段脏：型号规格混在名称里）匹配到「对码库」（几十万~上千万 SKU，含官方编码），逐行给出官方码 + 置信状态 + 候选供人工核对。

实战基准：9505 行总表 × 1346 万 SKU（30 个 xlsx）→ 建索引约 28 分钟（一次性），匹配 2 分钟，重跑 2 分钟。

## 管线总览

```
总表.xlsx ──P1 拆分──> splits.csv(名称/型号/规格三列)
对码库×N.xlsx ──P2 建索引──> duima_index.sqlite (sku 表 + B-tree + FTS5 trigram)
                     └────P3 匹配──> match_results.csv (27位码/状态/依据/备选)
                     └────P4 交付──> 已对码.xlsx(总表+7列) + 抽检核对表.xlsx + 统计sheet
总表.xlsx ──P1.5 导出──> ents.csv(厂商/主供应商，若总表有)
```

五个原语都在 `templates/`，复用时拷到项目 `scripts/` 下，改各自头部 CONFIG 段即可：

| 原语 | 文件 | 干什么 | 复用要改什么 |
|---|---|---|---|
| P1 拆分 | `split_names.py` | 名称字段拆出 名称/型号/规格（括号平衡解析 + 型号/规格 token 分类 + 尺寸串扫描） | 输入表名、sheet、名称列名、外配标记列 |
| P2 索引 | `build_index.py` | 对码库流式导入 SQLite：raw 列 + 归一化列 n_*，B-tree 索引，文件级断点去重 | 库文件名前缀、**COLS 列下标映射**（最重要） |
| P3 匹配 | `match_codes.py` | 分层匹配 + 打分状态机 + 行级断点续作 + 回写 xlsx | 列名、输出文件名、打分阈值（一般不用动） |
| P4 抽检 | `make_audit.py` | 按状态分层随机抽样，附 Top1-3 候选生成核对表 | plan 里各状态抽样数 |
| P5 交付 | `split_sheets.py` / `stats_sheet.py` | 按使用年份拆时间窗 sheet + 覆盖率统计矩阵 | 年份列名、时间窗口径 |

## 匹配策略（P3 核心，按优先级）

1. **厂家锁定 + 型号双向前缀**（最强）：总表「厂商/主供应商」归一后匹配库内企业（精确→子串，≥4字符），再在该企业 distinct 型号集里做双向 startswith。注意库内型号常是简写（`LPPMT`），总表是完整 token（`LPPMT12*16cm`），所以必须 `m.startswith(lm)` 方向。
2. **型号精确** `n_model = ?`（短 token <5 字符须过名称/规格一致性闸门，防 CEA/Burs 这类英文词撞名）
3. **型号前缀** `n_model LIKE 'x%'`（长 token 优先，需 `PRAGMA case_sensitive_like=ON` 才走索引——n_* 列已小写归一）
4. **名称 FTS5**（trigram 分词器支持中文子串）`WHERE n_item LIKE '%x%'` 取 rowid → 回 sku 表；整名 0 命中退到首段
5. 打分：规格一致 +2 / 名称 bigram 覆盖率 / 型号命中 +0.5 → 状态机

## 状态机（10 种，直接进交付表）

- `厂家型号唯一命中` / `厂家型号取Top1` —— 厂家锁定，最高/高置信
- `型号唯一命中` / `多候选取Top1` / `名称匹配取Top1` / `名称唯一命中` —— 可采纳
- `厂家型号待人工` / `多候选待人工` —— 码已填（建议值），需人工确认
- `未匹配` —— 码留空，弱命中参考放备选列
- `非耗材(外配药品)` —— 源表外配标记行，跳过

## 铁律与防坑（实战验证过，直接抄）

1. **归一化双端一致**：`norm()` = NFKC + 小写 + 去空白/连字符/波浪/中点 + `×/x→*` + `度→°`。总表端和库端必须同一套，建索引时存 n_* 列，匹配时只比 n_*。
2. **短 token 闸门**：型号 token <5 字符时，候选必须满足「名称 bigram 覆盖率 ≥0.2 或 规格命中」才采纳。
3. **分层守卫**：每一层匹配外层必须 `if not cands:` 守卫，否则下一层会把上一层的候选**覆盖成空**（今天踩过，全量 0 命中排查 1 小时）。
4. **FTS5 主键是 rowid**：`SELECT rowid FROM fts_name`，不是 id；辅助表回查用 `content='sku', content_rowid='id'`。
5. **断点续作**：匹配结果每 200 行 append 到 `match_ckpt.csv`，重跑跳过已完成行；换匹配策略时 `rm match_ckpt.csv` 全量重跑（2 分钟，别舍不得）。
6. **流式读大 xlsx**：`openpyxl.load_workbook(read_only=True)` + `iter_rows(values_only=True)` + 5 万行一批 `executemany`；SQLite 开 `PRAGMA journal_mode=WAL`。
7. **弱命中宁缺毋滥**：名称弱命中（分数 <1.5）标未匹配而非给错码；「待人工」行的码可以填建议值。
8. **抽检验证**：按状态分层抽 30+ 条附 Top1-3 候选给人核对，重点核「取Top1」类。

## 性能参考

- 1346 万 SKU 建索引（含 FTS5 trigram）：约 28 分钟，一次性；对码库更新后重跑（文件级断点，只增量新文件）
- 全量匹配 9505 行：约 2 分钟（含厂家型号集解析）
- 企业名解析用 Python dict 缓存（unique 厂商 × 库内企业子串匹配），不要进 SQL
- 大企业的 distinct 型号集（几千~几万）Python 侧前缀匹配即可，别再发 SQL

## 复用步骤（新项目的标准动作）

1. 看总表：确认名称列、型号/规格混入情况、有无厂商/主供应商/使用年份列
2. 看对码库：打开 1 个文件确认列结构（注册名/通用名/企业/规格/型号/官方码在哪列）
3. 拷 `templates/` 到项目 `scripts/`，改 CONFIG：build_index 的 COLS 列下标、match_codes 的列名与输出名
4. 跑 P1 拆分 → 抽 10 行人眼确认拆对 → P2 建索引 → P3 匹配（先 `MATCH_LIMIT=10` 小样本看状态）→ 全量
5. P4 抽检表给用户核对 → 反馈偏差改规则重跑（2 分钟级）→ P5 交付
