# 技术设计纲要

> 本文件是设计文档的规范源（canonical template），全局唯一。
> agent 接到复杂任务时读取本文件，按其结构产出 `<工作方向>-design.md`。
> 触发条件与纪律见 `constraints-inject.md` 的「先计划再执行」。

## 何时需要设计文档

满足任一：涉及 2+ 文件改动 / 跨模块或架构影响 / 修复 bug（需定位根因）/ 意图歧义或多实现路径。

**技能任务特例**：任务命中某技能（见 constraints-inject.md 技能目录），且技能内有用户选项（主题/图片/风格等必问项）时，按「意图歧义」处理——先 `read skill://<名>` 拿到选项清单再规划，选项确认点必须进计划/todo。

## 文档结构（<工作方向>-design.md）

1. **标题**：一句话说清目标
2. **问题根因分析**（修复类任务逐条列出）
   - 现象：用户可感知的症状
   - 根因：定位到具体对象 / 机制，不止说"有问题"
   - 修复：具体做法，到函数 / 字段级
3. **实现计划**：按改动分节，每节标
   - `文件:` 路径
   - 具体改动点（要点列表，到函数 / 字段级）
4. **修改文件清单**：表格（文件 ｜ 改动范围）

## 流程

写 doc → 用户确认计划 → 逐步执行（对照 doc，完成一步勾一步）→ 跨会话恢复时先重读 doc 再继续。

## 放置与命名

- 设计文档：`<当前项目>/design/<工作方向>-design.md`
  - `<当前项目>` 指你正在处理的项目目录（如 `workspace/Tiffa开发`），**不是** Tiffa 应用根目录 `E:\Tiffa`
  - `<工作方向>` 用 kebab-case 简短 slug 描述本次主题，如 `session-robustness`
  - 同一项目多次设计各占一文件，不覆盖，便于回顾
  - `design/` 子目录建在当前项目目录下（非 workspace 根）
- 本纲要：`data/memory/design-outline.md`（全局规范源，命名勿改）
