# 四重记忆系统

## 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  L1  USER.md       用户身份偏好            零延迟注入，每轮必读  │
│      "我叫张三，偏好 Q8_0 量化"                                │
├─────────────────────────────────────────────────────────────┤
│  L2  MEMORY.md     跨项目全局事实          零延迟注入，内核原生  │
│      "用户有 RTX 5090，NSSM 管服务"                            │
├─────────────────────────────────────────────────────────────┤
│  L3  PROJECT.md    当前项目架构/决策        零延迟注入，按 cwd 隔离│
│      "本项目用 SQLite，缓存目录在 data/"                        │
├─────────────────────────────────────────────────────────────┤
│  L4  Mnemopi       语义记忆（RAG）         autoRetain + manual recall│
│      三层内容的向量索引，跨项目语义搜索                           │
└─────────────────────────────────────────────────────────────┘
```

## L1: USER.md

- 内核原生加载，每轮注入
- 内容：用户亲口告知的身份、偏好、习惯
- 维护：用户自行编辑或 agent 代写

## L2: MEMORY.md

- 路径：`data/memory/MEMORY.md`
- 内核原生加载，跨项目共享
- 内容：agent 推断的全局事实（硬件、服务、通用约定）
- 约束：控制在 30 条以内，避免撑爆 context

### 当前内容示例

```markdown
## 产物存放铁律
- 所有产物只能放在当前对话所在项目的文件夹（cwd）内
- 严禁在 workspace 根目录下直接写文件

## 禁止无意义重复
- 输出必须简洁推进，每句话都有实质内容
```

## L3: PROJECT.md

- 路径：`<项目根目录>/PROJECT.md`
- 由扩展 `before_agent_start` hook 管理：
  - **首次对话**：自动生成脚手架（项目概述/关键决策/注意事项/外部服务）
  - **每会话开头**：读取并注入 system prompt
  - **会话中**：agent 用 write 工具持续维护
- 按 cwd 隔离：不同项目各有独立 PROJECT.md

### 脚手架模板

```markdown
# PROJECT.md — {dirName}

> 由 Tiffa 于 {date} 首次对话时自动生成。

## 项目概述
（项目目标、技术栈、关键路径）

## 关键决策 / 架构约定

## 注意事项 / 踩坑记录

## 外部服务 / 端口
```

## L4: Mnemopi 语义记忆

### 配置（settings 数据库写入）

| 参数 | 值 | 说明 |
|------|---|------|
| `mnemopi.scoping` | `global` | 所有项目共享同一库 |
| `mnemopi.autoRecall` | `false` | 关闭自动召回 |
| `mnemopi.autoRetain` | `true` | agent_end 自动 retain |
| `mnemopi.retainEveryNTurns` | `2` | 每 2 轮 retain 一次 |
| `mnemopi.recallLimit` | `10` | 最多召回 10 条 |
| `mnemopi.injectionTokenLimit` | `2000` | 注入上限 2000 token |

### Embedding 模型

- `BAAI/bge-small-zh-v1.5`（本地运行，~93MB ONNX）
- 无需 API，fastembed 加载
- 预热：实例 ready 后 3 秒发送 `/memory rebuild` 触发模型加载

### 工具

| 工具 | 说明 |
|------|------|
| `recall` | 语义检索历史记忆（跨项目），参数 `{ query }` |
| `retain` | 主动记住事实/决策（autoRetain 已开启，一般无需手动） |
| `reflect` | 反思/整理记忆 |
| `memory_edit` | 按 ID 更新/删除已召回的记忆 |

### 记忆分层协作

| 层 | 机制 | 用途 |
|---|------|------|
| 确定性注入 | PROJECT.md → before_agent_start | 项目级规范/决策 |
| 断片恢复 | gap-fill → compacting hook | 压缩时提取要点 |
| 全量积累 | Mnemopi global 库 autoRetain | 所有对话语义存储 |
| 全局铁律 | MEMORY.md（内核原生） | 跨项目通用事实 |
| 项目规范 | AGENTS.md（内核原生） | 当前项目架构/约束 |

## Gap-fill 断片补救

### 触发

`session.compacting` hook（上下文压缩时）

### 流程

```
1. 清理：删除 60 分钟前的旧 gap-fill / compact 文件
2. Compact dump：最近 50 条消息 → inbox/compact-{sessionId}-{ts}.txt
3. 提取（上限 60 条）：
   - 已读文件（避免重读）
   - 改动文件
   - 关键命令（排除 ls/cd/echo/Get-ChildItem/pwd/cls/clear）
   - 决策要点（正则：决定|配置|记住|改了|选了|用...方案|路径|踩坑|...）
4. 落盘：inbox/gap-fill-{sessionId}.md
5. 立即注入：return { context: [gapFill] }（不等下轮）
```

### 生命周期

- 创建：compacting 时
- 注入：压缩后立即返回 context
- 清理：60 分钟后自动删除（跨 session）

## 设计文档机制

复杂任务（多文件/跨模块/修 bug/意图歧义）触发设计文档流程：

```
读 data/memory/design-outline.md（规范源）
    → 在当前项目/design/ 下产出 <方向>-design.md
    → 用户确认
    → 逐步执行
    → 跨会话恢复时重读
```
