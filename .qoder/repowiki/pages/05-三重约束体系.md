# 三重约束体系

## 设计哲学

弱模型最怕约束写太多把上下文撑满。Tiffa 的约束分三层，各司其职，**总 token 成本趋近于零**：

```
第一重：TTSR 流式规则     → 零 Context 成本（模型输出时实时匹配）
第二重：行为约束注入       → ~500 token（before_agent_start 注入 system prompt）
第三重：tool_call 运行时拦截 → 零 Context 成本（事件驱动，不进 prompt）
```

## 第一重：TTSR 流式规则

### 机制

- 规则文件：`data/agent/rules/*.md`（YAML frontmatter + Markdown body）
- **流式匹配**：模型输出时逐 token 检测，`condition` 正则命中 → 立即中断生成
- **零 token 成本**：规则不进入 context，纯运行时拦截
- 中断后 Markdown body 作为纠正指导注入

### 规则文件格式

```markdown
---
description: "一行描述"
condition: "regex 或 [regex1, regex2]"
scope: "text" | "tool:write(*.ts)" | ["tool:edit(*)", "tool:write(*)"]
interruptMode: "always" | "never"
repeatMode: "once" | "after-gap"
---

Markdown 正文：告诉模型正确做法。
```

### 当前规则清单（12 条）

| 规则文件 | 拦截行为 | scope | interruptMode |
|----------|---------|-------|--------------|
| `no-bare-codeblock.md` | 代码块必须标注语言 | text | always |
| `no-filler-opening.md` | 禁止废话开头（"好的"/"当然"等） | text | always |
| `no-xml-toolcall.md` | 禁止 XML 格式调用工具 | text, thinking | always |
| `no-md-filepath-link.md` | 禁止 Markdown 链接包装文件路径 | text | always |
| `no-hardcoded-secrets.md` | 禁止硬编码密钥 | tool:write(*), tool:edit(*) | always |
| `no-git-add-all.md` | 禁止 git add -A | tool | always |
| `no-git-push-force.md` | 禁止 git push --force | tool | always |
| `cwd-file-placement.md` | 文件必须放在项目目录内 | tool:write(*) | never |
| `chinese-punctuation.md` | 中文语境用中文标点 | text | never |
| `tool-call-commentary.md` | 禁止工具调用废话 | text | never |
| `intermediate-files-to-temp.md` | 中间文件放 .temp/ | tool:write(*) | never |
| `no-repeated-tool-calls.md` | 禁止相同参数重复调工具 | tool | always |

### scope 说明

| scope 值 | 含义 |
|---------|------|
| `text` | 仅检测 assistant 文本输出 |
| `thinking` | 检测推理/思考摘要 |
| `tool` | 检测所有工具参数 |
| `tool:write(*.ts)` | 仅 write 工具且路径匹配 `*.ts` |
| `tool:edit(*)` | 仅 edit 工具 |

### interruptMode

| 值 | 行为 |
|---|------|
| `always` | 立即中断生成，注入纠正 |
| `never` | 不中断，仅注入警告（适合非致命问题） |

### /omfg 动态规则生成

用户输入 `/omfg <complaint>` → Electron 主进程拦截 → 构造 prompt → 模型直接 `write` 新规则文件 → 即时生效。

## 第二重：行为约束注入

### 文件

`data/memory/constraints-inject.md`（~43 行，控制在 500 字以内）

### 注入时机

扩展 `before_agent_start` hook → 读取文件 → 作为 `systemPrompt` 数组元素注入。

### 内容结构

```markdown
## 行为铁律
- 读文件：修改前必须先读取确认
- 3 次失败换方法
- 不猜测：标注"据我所知"
- 先计划再执行：3步以上列计划；复杂任务产出 design.md
- 错误先分析：不盲目重试
- 最小手术：只改需要的

## 专业任务必须发起 tool_call 调用 skill
- 触发词 → skill(name: "xxx") 映射表

## 沟通风格
- 中文回复、简洁、不重复
```

### 与 TTSR 的分工

| 维度 | TTSR | 行为约束 |
|------|------|---------|
| 检测时机 | 输出时（流式） | 启动前（注入） |
| 适合类型 | 格式/语法/模式匹配 | 语义/行为/流程 |
| token 成本 | 0 | ~500 |
| 修正方式 | 中断 + 纠正 | 预防（提前告知） |

## 第三重：tool_call 运行时拦截

### 实现位置

扩展 Hook 2（`pi.on("tool_call", ...)`）

### 拦截矩阵

| 触发条件 | 工具 | 响应 |
|---------|------|------|
| 危险路径（System32/Windows/Program Files） | edit/write | block |
| 配置文件自改（config.yml/models.yml/扩展.ts） | edit/write | block |
| workspace 根目录新建一级子目录 | edit/write/bash | block |
| .env / 密钥文件读取 | read/bash/shell | block |
| 连续 3 次静默工具调用 | 任意 | steer |

### 与前两重的协作

```
模型生成输出
    │
    ├── TTSR 流式检测（第一重）→ 格式违规则中断
    │
    ├── 决定调用工具
    │       │
    │       └── tool_call hook（第三重）→ 危险操作则 block
    │
    └── 行为约束（第二重）已在 system prompt 中预防
```

三层互补：TTSR 管输出格式，行为约束管决策倾向，tool_call 管最后防线。
