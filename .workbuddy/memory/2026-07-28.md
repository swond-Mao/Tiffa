- **根因（终，已修复）**：config.yml `mnemopi.embeddingModel` 值写的是 `"fast-bge-small-zh-v1.5"`（fastembed 短名），但内核 `aI2()` 函数用 `lC5` 映射表查找时，key 是 HuggingFace 全名 `"BAAI/bge-small-zh-v1.5"`（带 `BAAI/` 前缀）。短名查不到 -> `aI2` 返回 `null` -> `aC5()` 返回 `null` -> `xk0()` 返回 `null` -> `GE5()` 静默 return（无 error、无 warn、无 debug 日志）-> embedding 永远不写入 `memory_embeddings`。

  - 第一轮误诊为 settings 表缺 JSON 引号（错：settings 表根本不参与 `get("mnemopi.embeddingModel")` 的深层路径取值）
  - 第二轮误诊为 config.yml 嵌套层级错误（部分对：`mnemopi:` 确实应该是顶层节，但这只影响 scoping 等子配置，embeddingModel 值本身一直能被读到，只是值写错了）
  - 第三轮误诊为 fastembed 依赖树不完整（错：bun 隔离测试 EMBED_OK，依赖是好的）
  - **真正原因一直在眼皮底下**：config.yml 的值 `"fast-bge-small-zh-v1.5"` 少了 `BAAI/` 前缀
- **修复**：`data/agent/config.yml` 第 21 行 `embeddingModel: "fast-bge-small-zh-v1.5"` -> `embeddingModel: "BAAI/bge-small-zh-v1.5"`
- **验证**：bun 模拟内核完整链路 `lC5["BAAI/bge-small-zh-v1.5"]` -> `"fast-bge-small-zh-v1.5"` -> `FlagEmbedding.init({model:"fast-bge-small-zh-v1.5", cacheDir})` -> `EMBED_OK dims=512`。模型加载 359ms。
- **待用户操作**：重启 Tiffa，启动时会触发 `resuming interrupted embedding rebuild`，这次 `aI2` 会正确返回 `"fast-bge-small-zh-v1.5"`，embed worker 将成功产出向量写入 `memory_embeddings`。重启后查 bank 的 `memory_embeddings` 行数应 >0。
- **教训**：内核 `lC5` 映射表的 key 是 HuggingFace 全名（`BAAI/bge-small-zh-v1.5`），value 是 fastembed 短名（`fast-bge-small-zh-v1.5`）。config.yml 里必须写 HuggingFace 全名，不能写 fastembed 短名。OMP 官方文档未明确说明这一点。

## glm-5.2 重复输出排查（23:0x）
- **用户现象**：界面选 glm5.2、显示也是 glm5.2，重启后对话出现重复输出，怀疑后台实际不是 glm5.2。
- **验证模型身份**：直接 curl 火山方舟 `/api/coding/v3/chat/completions`（provider=volcengine，baseUrl=https://ark.cn-beijing.volces.com/api/coding/v3，model=glm-5.2）→ 返回 `"model":"glm-5.2"`，HTTP 200。**结论：后台确为 glm-5.2，"身份被掉包"怀疑不成立。**
- **真因（已锁定）**：glm-5.2 在该端点是**推理模型**——正式答案在 `reasoning_content`（思考链），`content` 在思考阶段为空。models.yml 里该模型配 `reasoning: false`，内核（openai-completions）按非推理模型只读 `content`，读到空/不完整就反复续写同一 prompt → 重复输出。
  - 实测：max_tokens=60 → content 空、reasoning 1491 字、finish_reason=length；max_tokens=4000 → content 71 字正式答案 + reasoning 1139 字。
  - 内核逻辑：`Z.thinkingFormat==="zai" && W.reasoning` 才消费 `reasoning_content`；thinkingFormat:"zai" 对 GLM 类模型自动判定。故 `reasoning: true` 即触发正确路径。
- **修复建议（待用户确认，未改盘）**：`data/agent/models.yml` 的 volcengine/glm-5.2 条目 `reasoning: false` → `reasoning: true`。改前按项目约定需贴全文确认。
- **附带发现**：session-model-map.json 是"每会话实际调用的 provider/modelId"真相来源；今日日志 data/log/2026-07-28.jsonl 不记录模型名（只记 session_stop/tool_result 事件），不能用来证伪模型身份。
