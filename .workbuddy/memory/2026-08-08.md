## 会话收尾记流水账——内核事件核对 + 粒度设计（用户提问触发）
- 用户质疑：若会话收尾每句话都记，就不是真流水账。核内核事件全集（`shared-events.ts`）：可用会话级收尾事件有 `agent_end`（193行，payload=`messages:AgentMessage[]`+`willContinue?`）、`turn_end`（212行，每轮）、`session_stop`（已订阅，1455行）、`session_shutdown`。**没有真正的"会话关闭/进程退出"之外的更粗粒度事件**，但 `agent_end` 已是最佳工作单元边界。
- **粒度结论（解决"每句话都记"担忧）**：主触发器用 **`agent_end`**（= 用户一条指令触发的完整 agent 运行，内部可能多轮工具调用/多句话，只在结束时记一笔），**绝非每句话/每轮工具调用**。再叠加两层控制：① **去噪门槛**——本次运行须有实质产出（写/改文件、跑 bash、或回复有实质长度），纯"继续/好的"空转不记；② **复用现有 `PROGRESS_SUMMARY_PROMPT`** 让旁路模型把本次运行提炼成一行，模型判无正事则返回空跳过。③ **保留跨天聚合**——即使底层记了多笔，日报只提炼成几句重点（明细在 log.md 细、报告在 PROJECT.md 粗）。
- **必须过滤 `willContinue`**：内核 auto-retry 触发的 agent_end 不是真结束，记了会重复。
- **与原 git-commit 触发对比**：原一行=一次 commit（漏掉纯对话/配置/记忆类工作，且用户不在 Tiffa 提交就全漏）；agent_end 一行=一次实质 agent 运行，覆盖所有在 Tiffa 真实发生的工作，粒度更贴合"进度沉淀"。
- **待用户拍板**：是否采用 agent_end+去噪+日报聚合 改写流水账种子（替换 git-commit 触发）。尚未动手改代码。
