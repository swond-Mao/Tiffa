# 2026-07-29 工作日志

## Tiffa 实例管理三缺陷修复（P0）

用户反馈三个症状：①切对话/项目时 omp 静默崩溃不重启、丢最后一段对话；②设的默认模型跳回 minimaxM2；③新建对话默认模型也错。

派 Explore agent 深入 `electron/main.js`(实际 2279 行) 定位，确认**不是单纯竞态**，是三个独立架构缺陷：

### Bug2 — 切换时静默崩溃不重启（最严重）
- **根因 a**：`activate`/`activateSession` 的 ready 轮询进程退出时无条件 `instances.delete(key)`，但 exit handler 3 秒后 `start()` 在同一实例对象上重建 process——实例已不在 map → 孤儿进程，renderer `getBySessionId` 返回 null → 看似"没重启"。
- **根因 b**：`shouldRestart` 要求 `code !== 0`，切换触发的异常 clean exit(code===0) 不重启但实例已 delete → 静默消失。
- 附带发现：`forceKill` 是死代码（全仓库无调用），AGENTS.md 的 stall→forceKill 升级实际不存在。

### Bug3 — 切换丢失对话
- `switchToSession`(app.js:1678) 对旧实例零干预：不 abort、不等 agent_end、不 flush。旧实例被 LRU 淘汰时 `taskkill /F /T` 强杀，正在生成的消息来不及写完 JSONL → 切回时历史缺失。
- `_evictLRU` 只跳过 activeKey，不跳过 agentRunning，会误杀正在等 LLM 的实例。

### Bug1 — 模型跳回 minimaxM2（P1，本次未动）
- `tiffa:setModel`(main.js:762) 只转发不落盘，持久化在 renderer(localStorage+session-model-map.json)。
- 新进程靠 renderer 异步补发 setModel（try/catch 吞错），且新进程 ready 后发 `config_update` 上报默认模型，renderer(app.js:600) 无条件 `state.currentModel = event.model` 覆盖 → 竞态冲掉用户设置。

## 落盘改动（main.js 5 处 + app.js 1 处）

main.js:
1. exit handler `shouldRestart` 去掉 `code !== 0`（常驻 CLI 非主动退出均视为崩溃）。
2. `activate`/`activateSession` 两处轮询：进程退出时 `willRestart` 则保留实例占位，不 delete。
3. `activate`/`activateSession` 两处复用分支：实例重启中(ready=false 且 process 退出)则等待 ready(≤10s)；统一返回 `{inst,ready}`（原返回 inst 不一致）。
4. `_evictLRU` 跳过 `agentRunning` 实例。

app.js:
5. `switchToSession` 开头：旧实例 agentRunning 时先 `abort` + 等 `agent_end`(3s 超时兜底) 再切。

`node --check` 两文件语法通过。重启闭环验证：exit→_cleanup(ready=false)→shouldRestart→3s start()→新 process ready 事件→ready=true(crashCount 归零)；复用等待能正确结束。`closeByKey` 走 kill() 设 userKilled=true，不受 shouldRestart 改动影响。

## 新建对话丢内容（既存缺陷止血）

用户测试反馈：对话运行中新建对话，原对话内容完全消失。

**诊断：非本轮回归。** 已排除：
- 新建对话(按钮 app.js:1503→1530-1581)不走 switchToSession，abort 改动不触发
- 新建对话走 activateSession spawn 分支，未改返回值
- Bug2(b) 让 code===0 也重启，但新建对话不 kill 旧实例，旧实例不退出
- _evictLRU 改跳过 agentRunning，反而保护运行中旧实例不被误杀

**根因（既存缺陷）**：新建对话 1553 直接 `dom.messages.innerHTML=''` 清屏，**没有像 switchToSession(1712-1721) 那样缓存旧对话 DOM 到 sessionMessageCache**。切回旧对话时只能靠 loadSessionHistory 从 JSONL 读，而运行中的消息往往没 flush → "完全消失"。用户之前测"切换崩溃"没暴露，切换修好后测新建对话才暴露。

**止血**：app.js 1530 新建对话开头补上旧对话 DOM 缓存 + agentRunning 保存（对齐 switchToSession）。旧实例不 abort，让后台继续跑完生成（JSONL 会补全），切回时优先从 DOM 缓存恢复。

注意：DOM 缓存是新建时刻快照，旧实例后台续跑的新消息不在缓存里，需切回后 loadHistory 补全——这是后续优化点。

## switchToSession abort 回滚（修复"后台停了"回归）

用户测试反馈：切换对话后旧对话立刻停了，没在后台继续跑。

**根因：上一轮 Bug3 修复错误。** 在 switchToSession 加了"切换前 abort+flush 旧实例"，强制停掉旧实例——与多实例并行架构冲突。用户要的是切换后旧对话后台继续跑。

**回滚**：去掉 switchToSession 的 abort 逻辑，只保留 agentRunning 状态保存（切回时恢复 UI 指示）。

**防丢对话改为靠三层保障**（不靠 abort）：
1. main.js `_evictLRU` 已跳过 agentRunning 实例 → 不被强杀
2. switchToSession DOM 缓存 → 切回即时恢复
3. 旧实例后台跑完 flush JSONL → loadHistory 切回补全

正确的多实例并行行为：切换不干预旧实例，让它后台跑完，切回时从缓存+JSONL 恢复。

## handleEvent 缺失 sessionId 路由（核心缺陷，导致按钮不变+内容污染）

用户反馈：切到没运行的对话，发送按钮没从停止变发送；旧对话任务"实际停了"。

**根因（架构性缺陷）**：main.js `_handleEvent`（307-308）给每个事件打 `_sessionId` 标记后广播给 renderer，但 renderer `handleEvent`（app.js:512）**完全没用 `_sessionId` 过滤**——516 行注释写着"按 sessionId 路由"，代码是空的。所有实例的事件全盘操作全局 `state.agentRunning`、渲染到当前 DOM。

后果：
1. 旧实例后台发 `agent_start`/`prompt_result` → `state.agentRunning=true` 覆盖当前（按钮卡在停止）
2. 旧实例发 `message_delta` → 渲染到当前对话 DOM（内容混乱/消失）
3. 切回旧对话，sessionAgentRunning 可能是脏数据（被旧实例事件用错误的 activeSessionPath 写过）

**修复**：handleEvent 开头加 sessionId 路由——`event._sessionId` 非空且≠activeSessionId 的后台实例事件，只更新该 sessionId 对应的 sessionAgentRunning 映射（切回时正确恢复状态），不渲染 DOM、不改全局 state。切回时从 JSONL loadHistory 补全后台跑完的内容。

`findSessionPathById`（app.js:164）复用现有反查逻辑，通过 activeSessionPaths 找后台实例的 path。

## sessionId 迁移缺失（切回丢上下文根因，main.js 修复）

用户补充诊断线索：切回旧对话让它继续，它说找不到上下文，说明切回去对话 id 变了。

**根因（设计缺失，文档未覆盖）**：
1. 新建对话 → 客户端生成 `tempSessionId`(crypto.randomUUID) → main.js 用 `_key(cwd, tempSessionId)` 存实例
2. 发首条消息 → CLI 分配真实 sessionId 写进 `.jsonl` 文件名 → `session_switch` 事件返回真实 `sessionPath`
3. renderer 迁移：`activeSessionId` 更新为从文件名提取的 `realSessionId`（app.js:672-676）
4. **main.js 完全不知情**：`TiffaInstance.sessionId` 永远是 tempSessionId，map key 也没更新
5. 切回 → renderer 用 `realSessionId` 调 `activateSession` → `_key(cwd, realSessionId)` 查不到 → spawn 新进程
6. 新进程读 JSONL 历史，但 CLI **进程内存里的对话上下文随旧进程死亡丢失** → "找不到上下文"
7. 旧实例(tempSessionId)变孤儿——renderer 再也查不到，靠 LRU 淘汰时强杀

**修复（main.js 3 处）**：
1. 顶部加 `_extractSessionIdFromPath` 工具函数（与 renderer extractSessionId 一致，正则提取 UUID）
2. `TiffaInstanceManager` 加 `migrateSessionId(cwd, oldId, newId)` 方法：删旧 key、用新 key 重新 set、同步 activeKey 和 spawning Map
3. `TiffaInstance._handleEvent` 拦截 `session_switch`：提取 realSessionId，若≠当前 sessionId 则调 `tiffaManager.migrateSessionId` 并更新 `this.sessionId`

闭环：CLI 发 session_switch → main.js 拦截 → 迁移 map key + activeKey → renderer 用 realSessionId 切回 → `_key(cwd, realSessionId)` 匹配到原实例 → 复用进程，CLI 内存上下文不丢。

注意：`session_switch` 事件经 `_handleEvent` 处理后仍会 forward 给 renderer（没 return），renderer 的迁移逻辑(app.js:638)保持不变，两边各自完成自己的迁移职责。

## 后台实例审批卡死 + 响应路由错误（双缺陷叠加）

用户反馈：A 对话运行中，切到 B 发消息，B 跑起来了，但 A 又停了。

**根因（两个缺陷叠加）**：
1. **renderer 路由丢弃后台审批请求**：上一轮加的 sessionId 路由(app.js:519)把所有非当前实例事件 `return` 掉，包括 `extension_ui_request`。A 后台跑遇到需审批的工具调用 → 事件被丢弃 → A 死等响应 → 卡住不动。
2. **main.js extensionResponse 发错实例**：`tiffa:extensionResponse`(main.js:896) 用 `_active()` 发响应（当前活跃实例），不是发请求的实例。即使请求没被丢弃，用户响应后也发给 B → A 收不到。

**修复（3 文件）**：
- **main.js** `tiffa:extensionResponse` 加 sessionId 参数，按 sessionId 路由到发请求的实例（getBySessionId 回退 _active）
- **preload.js** `extensionResponse` 透传第三参数 sessionId
- **app.js** handleEvent 路由：`extension_ui_request` 不 return，透传到 handleExtensionUI；handleExtensionUI 提取 `event._sessionId`，封装 `resp()` 统一带 sessionId 调 extensionResponse

**后台审批 UX 问题（待优化）**：后台实例的审批弹窗会弹到当前视图，干扰当前对话。当前先保证不卡死（弹窗可响应），后续可改为：后台实例审批请求排队/通知，或非 yolo 模式下后台实例自动确认。

## 模型/审批的对话级绑定现状（用户询问）

**模型**：已部分支持对话级。`sessionModelMap`（app.js）按 sessionPath 存 {provider, modelId}，切换/新建对话时 restoreModelIfAvailable 重放。但 main.js 不持久化，新进程靠 renderer 补发 setModel（竞态见 Bug1）。
**审批**：当前是 cwd 级（项目级），非对话级。`state.approvalMode` 单一全局变量，localStorage 按 cwdKey 存（`tiffa-approvalMode-<cwd>`），writeApprovalMode 写全局配置。多对话同项目共享审批模式。要做对话级绑定需改 state 结构 + 持久化 key + writeApprovalMode 支持对话级。优先级低于 P0 修复。
