> 基于 `@oh-my-pi/pi-coding-agent` v17.2.2 的便携 AI 工作台
> Electron 桌面壳（React + TypeScript 渲染层）+ Bun 内核子进程 + JSONL 协议
>
> 文档版本：v3（2026-08-11）｜对应 commit `4819ed8`

## 一、总体架构

```
┌──────────────────────────────────────────────────────────┐
│                    Electron 桌面壳                         │
│  main.js (主进程 ~3740行)   renderer/src/ (React + TS)    │
│  ├─ TiffaInstanceManager    ├─ components/ (ChatView 等)  │
│  ├─ 65 个 IPC handler       ├─ stores/ (Zustand, 5 个)   │
│  ├─ 窗口/主题/图标管理       ├─ services/ (eventRouter)   │
│  └─ /omfg 命令拦截           └─ hooks/ + vite 构建产物     │
└──────────────┬───────────────────────────────────────────┘
               │ JSONL over stdin/stdout
┌──────────────▼───────────────────────────────────────────┐
│              Bun 内核子进程 (cli.js)                       │
│  ├─ Agent 核心（工具调用 / 会话管理）                        │
│  ├─ Mnemopi 记忆引擎（SQLite + ONNX embedding）            │
│  ├─ TTSR 流式规则引擎（13 条）                              │
│  └─ 扩展加载器 -e plugins/claude-mode-extension.ts        │
│                  -e plugins/computer-use-extension.ts     │
└──────────────────────────────────────────────────────────┘
```

**通信协议**：每行一个 JSON 对象（JSONL）。主进程向子进程 stdin 写命令帧，从 stdout 读事件帧。

## 三、记忆层级

| 层 | 载体 | 内容 | 生命周期 | 注入方式 |
|---|------|------|---------|--------|
| L1 | `data/memory/USER.md` | 用户身份/偏好 | 永久 | 每会话全文注入 |
| L2 | 全局 bank | 跨项目使用历史 | 永久积累 | 语义召回 |
| L3 | `<项目>/PROJECT.md` | 项目纲领/铁律 | 人工维护 + 自动生成脚手架 | 每会话全文注入 |
| **L-踩坑** | **`<项目>/docs/踩坑记录.md`** | **精选踩坑档案（根因/修复/关键文件/教训），仅记确定踩坑** | **人工精选，长期保留** | **不注入，排查时按需读取** |
| L4 | 项目 bank | 项目近期进度 | 自动积累+退化 | 语义召回（优先） |
| L5 | gap-fill | 本次对话瞬时上下文 | 60 分钟 | 压缩时即时注入 |

> **L-踩坑 读取优先级**：用户提及「以前我们怎么实现」时，先 `read` `<项目>/docs/踩坑记录.md`（精确档案），不够再语义召回（`recall`）。

> **隐私设计**：USER.md / MEMORY.md 为运行时个人数据（AI 自动填充/覆写），**已 gitignore 不入库**，模板由 install.ps1 第 6 步生成（Ensure-MemoryTemplate，已存在则跳过）。AI.md / constraints-inject.md / design-outline.md 为项目级模板，正常入库。

### Mnemopi 配置（settings 数据库，实测值）

```
mnemopi.embeddingModel      = BAAI/bge-small-zh-v1.5
mnemopi.scoping             = per-project-tagged   # 双层召回
mnemopi.autoRecall          = true                 # 首条消息自动召回
mnemopi.autoRetain          = true                 # 每 2 轮自动写入
mnemopi.retainEveryNTurns   = 2
mnemopi.recallLimit         = 10                   # 单次最多召回 10 条
mnemopi.injectionTokenLimit = 2000                 # 注入上限
mnemopi.debug               = true
```

> **写入方式**：必须用 `settings` 数据库直接写入。config.yml 的嵌套写法
> （`memory.mnemopi.scoping: global`）**不生效**，已验证。

**scoping 三种模式**：
- `global`：全部写全局 bank，只召回全局
- `per-project`：写项目 bank，只召回项目
- `per-project-tagged`（**当前生效**）：写项目 bank 打标签，召回时并行搜项目 + 全局，项目优先

**数据库位置**：`data/agent/memories/mnemopi/mnemopi.db`（全局 bank），项目 bank 在 `banks/` 子目录。

### L3 PROJECT.md 自动脚手架（扩展 v6.2）

`before_agent_start` hook 检测到项目根目录首次对话时，自动生成 `PROJECT.md` 脚手架并确定性注入 system prompt——不依赖语义召回，保证纲领每轮必达。

### L5 gap-fill 断片补救

`session.compacting` hook 触发，四步：
1. **compact dump** → `data/memory/inbox/compact-{sessionId}-{ts}.txt`（最近 50 条消息原文，单条截断 2000 字符）
2. **提取** 改动文件 / 关键命令（排除 ls/cd/echo）/ 决策要点（正则去噪，上限 60 条）
3. **落盘** → `data/memory/inbox/gap-fill-{sessionId}.md`
4. **立即注入** 返回 `{context: [...]}`，不等下一轮；60 分钟后跨 session 自动清理

> ⚠️ `claude-mode-extension.ts` 文件头注释声称「gap-fill 已删除 → Mnemopi autoRecall 覆盖」，
> 这是**过期注释**。代码中 gap-fill 仍完整存在（22 处引用 + `session.compacting` hook 在册）。

### 写入路由规则

| 用户说的话 | 写入位置 |
|-----------|---------|
| "这个项目必须/不能 xxx" | PROJECT.md（铁律） |
| "记录到项目记忆" | PROJECT.md |
| 项目目标/里程碑 | PROJECT.md（非必要不写） |

```
第一重：TTSR 流式规则（零 Context 成本）
  data/agent/rules/*.md — 13 条
  模型输出时实时正则匹配，违规立即拦截，不占 token

第二重：before_agent_start Hook（语义约束）
  data/memory/constraints-inject.md

### 扩展 Hook 清单（6 个）

| # | 事件 | 功能 |
|---|------|------|
| 0 | `session_start` | 移除 eval/hub 工具 |
| 1 | `before_agent_start` | 注入 USER.md + PROJECT.md（含脚手架生成）+ 静默计数重置 |
| 2 | `tool_call` | 危险拦截 + 熔断（连续 block 3 次强制终止）+ 技能强制 + 静默检测 |
| 3 | `session.compacting` | gap-fill 提取 + compact dump + 即时注入 |
| 4 | `session_stop` | error 续行（最多一次，5 秒延迟） |
| 5 | `tool_result` | 审计日志（JSONL） |

**熔断机制**：同一轮内被 `block` 累计 3 次 → 强制终止并要求换方法，防止弱模型反复重试撑爆 context。

**技能强制**：调 `comfy.py` / `craftman.py` 等技能脚本前，必须已 `read skill://<name>` 加载步骤且已用 `ask` 询问用户，否则 block。

**/omfg 命令**：`/omfg <抱怨>` → Electron 主进程拦截，模型生成 TTSR 规则文件，即时生效。

## 五、多实例管理（TiffaInstanceManager）

| 参数 | 值 |
|------|---|
| 最大实例数 | `MAX_INSTANCES = 8` |
| 通信 | JSONL over stdin/stdout |
| 就绪检测 | 100ms 轮询，最长 15 秒 |
| LRU 淘汰 | 淘汰 `lastActiveTime` 最久远且非 `agentRunning` 的实例 |
| 崩溃重启 | 最多 3 次（`maxCrashRestart`），延迟 3 秒 |

### 生命周期修复要点（2026-07-29，P0）

1. **重启实例不脱离 map**：ready 轮询检测到进程退出时，若 `willRestart`（`!userKilled && crashCount < max`）则**保留实例占位**，不 `instances.delete`。否则 exit handler 3 秒后重建的进程会变成 renderer 拿不到的孤儿（表现为「点了没反应」）。
2. **`code === 0` 也重启**：`shouldRestart` 去掉 `code !== 0` 条件。常驻 CLI 不应自行退出，任何非 `userKilled` 的退出都视为崩溃。
3. **切换会话先收尾**：`switchToSession` 在切换前若 `agentRunning` 则 `abort` + 等 `agent_end`（3 秒超时兜底），避免 LRU `taskkill /F /T` 强杀丢失未写盘的 JSONL。
4. **`activate` / `activateSession` 统一返回** `{inst, ready}`；复用分支若实例重启中则等待 ready（≤10 秒）。

> `forceKill` 是死代码（全仓库无调用）。旧文档里「stall → forceKill 升级」实际不存在，
> stall 检测只在 renderer 侧做 abort。

### 会话删除 / 归档必须关实例

`sessions:deleteSession` / `archiveSession` 若只删文件不关实例，内核后续写盘会把 jsonl「复活」。

- main.js `_closeInstancesForSessionFile()`：按 `sessionFilePath` 或提取的 sessionId 匹配 → `inst.kill(true)` 同步杀 + 移出 map
- `sessions:deleteSession` 幂等（文件不存在也返回 success）
- 前端 `cleanupSessionMemory()` 统一清理 sessionModelMap / agentRunning / 消息缓存 / openTabs

**删除对话 = 杀实例进程**，与「关 tab 保留实例」是两种不同行为。

### ⚠️ 本地 provider 命名铁律

本地 provider 的 key **必须用内核约定名，不可自定义**（2026-08-01 改名，原 `qwen` / `qwen-remote`）：

1. **WebP 静默崩**：内核 `modelLacksWebpSupport()` 只按 provider key 匹配白名单
   （`ollama` / `ollama-cloud` / `llama.cpp` / `lm-studio` / `local-server`）。
   命中才 `excludeWebP: true`，拖拽 `frame.images` 与 `read` 两条路径都不再编码 WebP。
   否则 llama.cpp（stb_image 无 libwebp）收到 webp 会返回 **HTTP 200 + 空 choices**，
   内核当正常 stop 处理 → 连发空回复、无 error 事件，极难排查。
2. **远程中继特意选 `local-server`**：`append-only-context-mode.ts` 的 `LOCAL_INFERENCE_PROVIDERS`
   **不含** `local-server`，避免凭空打开 append-only 上下文。本地直连因 loopback 判定本就开着，改名后行为不变。
3. **`supportsTools` 必须为 `true`**：这不是工具开关而是**协议切换**。
   `sdk.ts` 的 `resolveDialect()` 在 `tools.format=auto`（默认）下，标 `false` 会从原生
   function calling 退化成 GLM in-band 文本协议——工具清单塞进 system prompt 每轮烧 token、
   格式易错乱、还会撞 TTSR `no-xml-toolcall`。
4. **撞名安全**：`model-registry.ts` 对内置 llama.cpp 的自动注册有 `configuredProviders.has()` 守卫，用户配置优先，不 merge。

**已废弃、勿重建的两条路**：
- 扩展层 webp 白名单（tool_result hook + models.yml `supportsWebp`）——只罩 tool_result，拦不住内核回转 webp，代码已删
- `OMP_NO_WEBP=1` 全局兜底——会连带牺牲云端 webp 压缩

**验证陷阱**：`cli.js models --json` 是固定十字段投影，**不输出** `supportsTools` / `supportsWebp`，
不能用它判断字段是否被 schema 剥离。正确做法：`ModelsConfigFile.relocate(path).tryLoad()` 直接看解析结果。

另：models.yml 手写 `imageInputDecoder: "stb"` 会被内核 schema 剥离（model 级 keys 固定，无此字段），别再试。

### 品牌图标构建管线

产物在 `electron/assets/`：
- `tiffa-icon.ico` — 手工构建的 7 尺寸（16/24/32/48/64/128/256，PNG 编码、带透明圆角）
- `tiffa-icon.png` — 原尺寸参考（托盘 / 跨平台备用）

两个接入点：
1. **窗口 / 任务栏**：`BrowserWindow` 的 `icon` 字段
2. **桌面启动器**：`tiffa-desktop.exe` 原本**没有任何图标资源**（只有版本信息 + 清单），
   用 `resedit` 新增图标组（`res.outputResource(exe)` → `exe.generate()`），
   资源项 2 → 10，体积 5120 → 128000 字节。原始文件备份为 `tiffa-desktop.exe.bak`。

**两个坑**：
- Pillow 的 `save(sizes=, append_images=)` 实测**只写出 1 个尺寸**。必须手工拼 ICONDIR + 目录项 + PNG 字节。
- resedit 临时文件删除会被沙箱拦截报错，但 exe 在报错前已 `copyFileSync` 覆盖完成，不影响结果。

复用脚本留在 `local_cache/`（已 gitignore）：`make_icon.py`（重生成 ICO）、`inspect_exe.js`（查资源）、`patch_exe.js`（重嵌图标）。

### 滚动跟随 = `followScroll` 三态机（React 版）

`src/` 内 `followScroll` 对象是滚动跟随的**唯一权威**，`scrollToBottom(force)` 只是薄壳
（`force → attach()`，否则 `schedule()`）。**新增滚动需求改控制器，别在调用点各自写 `scrollTop`。**

核心坑：`.messages` 的 CSS `scroll-behavior: smooth` 与流式逐 token 写 `scrollTop` **互斥**——
平滑动画被反复打断追不上 `scrollHeight`，落后超阈值后旧的 `nearBottom` 距离判定永久失效（表现为「跟丢」）。

规则：
1. 程序滚动一律临时 `scrollBehavior = 'auto'` 强制 instant，之后还原
2. 跟随态只由**用户显式意图**翻转（上滚轮 / 拖滚动条 / PageUp·Home / 触摸上滑 / 拖 minimap → `detach`），距底 ≤4px 才自动 `attach`
3. 会话恢复 `scrollTop` 后必须补 `followScroll.sync()`，否则历史中段会被拽到底

### 流式渲染铁律（防「小框刷字」）

流式消息挂 `.streaming` class，CSS `.message.streaming{content-visibility:visible}`——
`:last-child` 方案已弃（脆弱）。`textDelta` 事件必须立即追加渲染（useChatStore 有回归测试兜底）。

### 模型白名单（enabled-models.json）

`undefined` = 全部显示（由 models.yml 过滤兜底），只在用户**显式配置**时才激活白名单。

- 添加供应商向导**不得**在 `undefined` 时自动激活白名单。曾因 `onFinish` / `onSaveOnly` 直接 `enabledModels = allKeys`，把列表意外收窄成只有新供应商 → 删掉供应商后「取不到应有模型」。
- 删除供应商后若白名单整体孤儿化（剩余 key 的 provider 都不在 models.yml）→ 重置为 `undefined`。

### 三阶段强制流程

bun run test_embed.js           :: embedding 单元测试
bun run test_live_memory.ts     :: 实际进程端到端验证
```

### 常见坑

1. **Bun 跑 TS 需 `.ts` 后缀** — `.js` 文件里写类型注解会报语法错误
2. **PowerShell 引号** — 复杂 SQL 写成脚本文件再 `bun run`，不要内联
3. **embedding 维度** — 中文模型 512 维，英文默认 384 维，混用导致检索失效
4. **路径硬编码** — 一律用 `$env:PORTABLE_ROOT`，禁止写死 `G:/Tiffa`
5. **mnemopi 配置** — 只认 `settings` 数据库，config.yml 嵌套写法不生效
6. **本地 provider 命名** — 见第六节铁律，改名会引发 WebP 静默崩或协议退化
