### 模型列表为空但健康检查在线——provider 缺 apiKey 被内核整体过滤（2026-08-25 修复）

- **根因**：内核（oh-my-pi）`ModelRegistry.getAvailable()` 只收录「有 apiKey 或 `auth: none`（keyless）」的 provider；设置页序列化 models.yml 时 Key 留空会整行省略，导致该供应商从模型列表整体消失。健康检查（`settings:checkModelHealth`）是主进程直接 HTTP ping，不经过内核，所以照样显示在线——两条链路独立，"健康在线"不代表内核已收录。
- **修复**：① SettingsPanel `serializeModelsYaml` 中 apiKey 空值兜底写 `"none"`（与旁路模型 callCompletion/健康检查既有口径一致）；② 主进程启动自愈：对有 baseUrl、无 apiKey、无 auth 字段的 provider 幂等补写 `"none"`（备份 .bak-heal-apikey），顺带修复历史脏数据。
- **关键文件**：`renderer/src/components/SettingsPanel.tsx`（serializeModelsYaml）、`main.ts`（启动自愈块）、内核过滤点 `@oh-my-pi/pi-coding-agent/src/config/model-registry.ts` L2262。
- **教训**：models.yml 是「UI 序列化 → 内核注册表」两套语义的交界，任何字段省略策略都要对照内核 `getAvailable()` 的收录条件；本地无认证端点的惯例是显式写 `apiKey: "none"`。
